Agent Mesh connects agents, MCP tools and models across laptops, isolated sandboxes and Kubernetes. Nodes dial out, so no port opens, and no agent holds an API key.

How it works

One request through the mesh

Nothing is reachable by default. Nodes dial out over QUIC and TLS 1.3, and every call is checked by service name.

Identity and policy

agentmesh-control-plane

Verifies OIDC or bootstrap tokens, compiles Datalog policies, and signs short-lived Biscuit credentials. Off the data path.

Discovery and relay

agentmesh-router

Runs the Kademlia DHT and relays encrypted streams across NATs and firewalls without seeing plaintext payloads.

Local data-plane proxy

agentmesh-node

Runs beside your agent. Publishes and calls mcp://, a2a://, inference:// and egress:// over HTTP.

What it is

A network of named services

Agent Mesh is built for agent protocols rather than raw IP packets.

Not a flat L3 VPN

Calls go to service names

No virtual network interfaces or exposed machine ports (--network=none). Peers can only call published service names.

Not single-cluster only

One overlay for every environment

Connects agents on laptops, isolated sandboxes, VMs and Kubernetes clusters over one peer-to-peer overlay.

Not a siloed gateway

Plugs into the proxies you run

Integrates with Envoy (ext_proc, ext_authz), Istio and agent gateways through standard HTTP and OAuth token exchange.

Deployment

Four ways to run the node

Pick the footprint that fits your environment. All four speak the same mesh protocol.

01 · Sidecar or CLI

A local daemon with SKILL.md

Run agentmesh-node on a laptop, VM or Kubernetes pod. Agents learn how to find and call mesh services through a local SKILL.md or MCP server.

  1. Agent CLIreads SKILL.md
  2. agentmesh-node127.0.0.1:8080
  3. Remote peerQUIC / TLS 1.3
yamlconfig.yaml
version: "v1alpha1"
services:
  - type: mcp
    name: orders-db
    target_url: "http://127.0.0.1:3001/mcp"
  - type: inference
    name: local-llm
    target_url: "http://127.0.0.1:11434"

02 · Zero secrets

Sandboxes with no API keys inside

Run untrusted code in a container or microVM with no secrets in memory. The sandbox talks plain HTTP to agentmesh-node outside the boundary, which authenticates and injects credentials on egress.

  1. Sandbox0 keys in RAM
  2. Host nodeBiscuit verify
  3. egress:// APIinjects the secret
bashinside the sandbox
# Route outbound HTTP through the host node
$ export HTTPS_PROXY=http://host.internal:8080

# Call an external API without holding its key
$ curl https://api.github.com/repos/google/agentmesh

03 · Envoy and gateways

Istio and Envoy with ext_proc and ext_authz

Plug agentmesh-node into Envoy, Istio and agent gateways. Exchange platform JWTs at /oauth/token (RFC 8693) for task Biscuits and enforce policy on every tool call.

  1. Workload JWTOIDC / K8s SA
  2. Envoy or gatewayext_authz · ext_proc
  3. Mesh serviceDatalog check
bashRFC 8693 token exchange
$ curl -X POST http://127.0.0.1:8080/oauth/token \
  -d "grant_type=urn:ietf:params:oauth:grant-type:token-exchange" \
  -d "subject_token=$WORKLOAD_JWT" \
  -d "resource=mcp://orders-db"
✓ Issued attenuated Biscuit for mcp://orders-db

04 · In-process

Python and TypeScript SDKs

Embed Agent Mesh in your agent harness. Narrow permissions offline with session.attenuate() before you hand work to a sub-agent.

  1. Parent agentBlock 0 Biscuit
  2. attenuate()+ tar_block
  3. Sub-agentread-only scope
pythonsubagent.py
from agentmesh import MeshSession, Rule

sub = session.attenuate([
    Rule(service="orders-db", action="mcp:call",
         resource="mcp://orders-db/tools/list_orders")
]).seal()
# The sub-agent cannot call delete_order

Security

Biscuit tokens checked at every hop

Credentials are bound to the transport connection and verified locally by every node.

  • Stolen tokens stop working

    Every Biscuit carries the node's Ed25519 PeerID in Block 0, checked against the live QUIC and TLS 1.3 handshake.

  • Least privilege per task

    Verifiers require the control plane's Block 0 Datalog policy and every appended sub-agent tar_block to pass.

  • Secrets stay at the edge

    Agents use Biscuits inside the mesh; border nodes mint short-lived OAuth and STS JWTs or inject API keys on egress.
